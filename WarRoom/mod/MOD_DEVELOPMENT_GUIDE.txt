================================================================================
一、模组系统概述
================================================================================

节点模组（NodeMod）是战略地图管理器的扩展机制，允许开发者自定义节点的：
  - 外观渲染（替代或叠加默认的文本节点显示）
  - 交互行为（鼠标、键盘、悬停、右键菜单、拖放、双击等）
  - 数据序列化（保存/加载自定义数据到文档 JSON）
  - 编辑器界面（节点专属编辑器 / 全局模组设置界面）
  - 嵌入 Widget（如浏览器视图、视频播放器）
  - 连线钩子（允许/拒绝连接、连接创建/删除通知）
  - 键位绑定（自定义快捷键，在设置页统一显示）
  - 存档资源打包（图片、视频等外部文件打包到 mod_data 目录）

模组分为两类：
  1. 主模组（Primary Mod）：绑定到节点的 primary_mod_type，负责节点的核心外观
     - 一个节点最多绑定一个主模组
     - 返回 isPrimary() = true
     - 示例：ImageMod（图片节点）、VideoMod（视频节点）、WebMod（网页节点）

  2. 辅助模组（Auxiliary Mod）：绑定到 auxiliary_mod_types，叠加渲染/交互
     - 一个节点可绑定多个辅助模组
     - 返回 isPrimary() = false
     - 支持 shouldAutoAttach() 自动附加到新节点
     - 示例：AnnotationMod（标注模组）、徽章模组、状态指示模组

模组内部还有两个相关子系统：
  A. 键位绑定系统（KeyBinding + KeyBindingRegistry）：
     在 getKeyBindings() 中注册，主程序"键位设置"页面会统一展示并允许修改。
  B. 模组设置界面（hasSettings / createSettingsWidget / saveSettings）：
     返回 true 时，主程序"模组设置"页面显示 "设置" 按钮，弹出自定义 widget。

【步骤 1】创建模组类文件

在 mod/builtin/ 目录下创建新头文件（当前所有内置模组均为 header-only），
例如 MyMod.h：

    #pragma once
    #include "mod/NodeMod.h"
    #include "core/warroom/war_node.h"

    namespace warroom {

    class MyMod : public NodeMod {
    public:
        // ---------- 私有数据结构 ----------
        struct PrivateData {
            QString     somePath;
            QPixmap     cachedPixmap;
            int         mode = 0;
        };

        // ---------- 基础信息 ----------
        ModInfo getInfo() const override {
            return {
                "builtin.mymod",    // id 唯一，建议格式 "builtin.xxx" / "custom.xxx"
                "我的模组",         // 名称（UI 显示）
                "0.1.0",            // 版本
                "author_name",      // 作者
                "这是一个示例模组", // 描述
                ""                  // 图标（可选，预留）
            };
        }
        bool isPrimary() const override    { return true; }
        ModPriority getPriority() const override { return ModPriority::Normal; }

        // 其余接口按需要重写（见下文）
    };

    } // namespace warroom

【步骤 2】实现生命周期与序列化（主模组建议必写，辅助模组可选）

    // 节点创建/加载时：分配私有数据
    void* onCreateNode(WarNode* /*node*/, ::NodeGraphicsItem* /*item*/) override {
        return new PrivateData();
    }

    // 节点销毁时：释放私有数据
    void onDestroyNode(void* modData) override {
        delete static_cast<PrivateData*>(modData);
    }

    // 节点加载完成后（反序列化已完成）再做进一步初始化
    void onNodeLoaded(WarNode* node, void* modData) override {
        auto* d = static_cast<PrivateData*>(modData);
        // 这里可以根据 somePath 加载 pixmap、初始化 QMovie 等
    }

    // 节点保存前（serialize 前调用，通常不必写，可用于更新运行时缓存）
    void onNodeSaved(WarNode* /*node*/, void* /*modData*/) override {}

    // 保存：PrivateData -> nlohmann::json
    nlohmann::json serialize(void* modData) const override {
        auto* d = static_cast<PrivateData*>(modData);
        if (!d) return {};
        nlohmann::json j;
        j["path"] = d->somePath.toStdString();
        j["mode"] = d->mode;
        return j;
    }

    // 加载：nlohmann::json -> PrivateData
    void deserialize(void* modData, const nlohmann::json& data) override {
        auto* d = static_cast<PrivateData*>(modData);
        if (!d) return;
        if (data.contains("path") && data["path"].is_string())
            d->somePath = QString::fromStdString(data["path"].get<std::string>());
        if (data.contains("mode") && data["mode"].is_number_integer())
            d->mode = data["mode"].get<int>();
    }

【步骤 3】实现渲染与尺寸（主模组必写）

    // 主渲染入口。返回值：
    //   true  = 我已绘制了主体，后续默认背景/文本不再绘制
    //   false = 仅做叠加，继续绘制默认内容 + 后续模组
    bool onPaint(const ModRenderContext& ctx, void* modData) override {
        auto* d = static_cast<PrivateData*>(modData);
        QPainter* p  = ctx.painter;
        QRectF rect  = ctx.rect;
        const WarNode* node = ctx.node;
        // ctx.zoomLevel / ctx.isSelected / ctx.isHovered 也可用

        if (d && !d->cachedPixmap.isNull()) {
            p->drawPixmap(rect, d->cachedPixmap);
        } else {
            // 占位符（图片缺失 / 未加载的降级显示）
            p->setBrush(QColor(240, 240, 240));
            p->setPen(QPen(QColor(180, 180, 180), 1));
            p->drawRoundedRect(rect, 6, 6);
            p->setPen(QColor(120, 120, 120));
            p->drawText(rect, Qt::AlignCenter, "空模组");
        }
        return true;  // 主模组通常返回 true（替代默认绘制）
    }

    // 推荐尺寸（节点刚创建或切换模组时使用）
    QSizeF getPreferredSize(const WarNode* /*node*/, void* modData) const override {
        auto* d = static_cast<PrivateData*>(modData);
        if (d && !d->cachedPixmap.isNull())
            return QSizeF(d->cachedPixmap.width(), d->cachedPixmap.height());
        return QSizeF(200, 150);
    }

    // 最小尺寸（用户缩放节点时不会小于这个值）
    QSizeF getMinimumSize(const WarNode* /*node*/, void* /*modData*/) const override {
        return QSizeF(60, 40);
    }

【步骤 4】实现交互（鼠标/键盘/悬停，按需实现）

所有交互方法都返回 ModInteractionResult：
    Ignored  = 我没处理，继续给下一个模组/默认行为
    Handled  = 我处理了，不再给下一个模组，但默认行为仍可发生（罕见使用）
    Consumed = 我消费了事件，停止传递，阻止默认行为（常用）

示例：双击节点弹出对话框换图

    ModInteractionResult onMouseDoubleClick(QGraphicsSceneMouseEvent* /*event*/,
        const WarNode* node, void* modData) override
    {
        auto* d = static_cast<PrivateData*>(modData);
        QString file = QFileDialog::getOpenFileName(
            nullptr, "选择图片", {}, "Images (*.png *.jpg *.jpeg *.bmp *.gif)");
        if (!file.isEmpty()) {
            d->somePath = file;
            d->cachedPixmap.load(file);
            // 注意：修改后需要主动刷新节点显示
            // ModMenuContext 里有 requestNodeRefresh 回调，
            // 但这里可以通过 ModManager + 主程序消息机制实现。
            // 内置 ImageMod 里做法是通过向上转型 NodeGraphicsItem->scene()->update() 或
            // 直接在 NodeGraphicsItem 调用 update。
        }
        return ModInteractionResult::Consumed;
    }

键盘事件（示例：F5 切换模式）：

    ModInteractionResult onKeyPress(QKeyEvent* event,
        const WarNode* /*node*/, void* modData) override
    {
        if (event->key() == Qt::Key_F5) {
            auto* d = static_cast<PrivateData*>(modData);
            d->mode = 1 - d->mode; // 切换 0/1
            return ModInteractionResult::Consumed;
        }
        return ModInteractionResult::Ignored;
    }

悬停状态（可选）：
    onHoverEnter / onHoverMove / onHoverLeave

【步骤 5】右键菜单扩展（两类入口）

A. 节点"已启用该模组"时的菜单扩展（onContextMenu）

    bool onContextMenu(const ModMenuContext& ctx, void* modData) override {
        auto* d = static_cast<PrivateData*>(modData);
        if (!ctx.menu) return false;

        ctx.menu->addSeparator();  // 和默认菜单区分

        QAction* actA = new QAction("切换展示模式", ctx.menu);
        QObject::connect(actA, &QAction::triggered, [d, ctx]() {
            d->mode = 1 - d->mode;
            if (ctx.requestNodeRefresh)
                ctx.requestNodeRefresh(ctx.nodeId);  // 请求刷新节点 UI
        });
        ctx.menu->addAction(actA);

        return true;  // true 表示我加了分隔线（主程序用来布局）；
                      // 实际未加分隔线时返回 false 也可以。
    }

B. 节点"尚未启用该辅助模组"时也能在右键菜单显示入口（onContextMenuForNode）
   用于 "启用 XX 模组" 这种操作，仅辅助模组常用：

    bool onContextMenuForNode(const ModMenuContext& ctx) override {
        if (!ctx.menu) return false;
        QAction* act = new QAction("启用我的辅助模组", ctx.menu);
        QObject::connect(act, &QAction::triggered, [ctx]() {
            // 通过 ModManager 附加辅助模组（需要 NodeGraphicsItem*）
            // 具体实现参考 AnnotationMod。
        });
        ctx.menu->addAction(act);
        return true;
    }

【步骤 6】拖放支持（两种场景）

A. 拖放到"已有的节点"上（主模组/辅助模组都可以用）：

    bool canAcceptDrop(const QMimeData* mimeData,
        const WarNode* /*node*/, void* /*modData*/) const override
    {
        return mimeData && mimeData->hasUrls();  // 接受文件拖放
    }

    void onDrop(const QMimeData* mimeData, WarNode* /*node*/, void* modData) override {
        auto* d = static_cast<PrivateData*>(modData);
        if (mimeData->hasUrls() && !mimeData->urls().isEmpty()) {
            QString path = mimeData->urls().first().toLocalFile();
            d->somePath = path;
            d->cachedPixmap.load(path);
        }
    }

B. 拖放到"空白画布"直接创建节点并自动绑定本模组（主模组常用，
   对应 ImageMod 的拖图片到空白处自动建图片节点）：

    bool canCreateNodeFromDrop(const QMimeData* mimeData) const override {
        if (!mimeData || !mimeData->hasUrls()) return false;
        for (const auto& url : mimeData->urls()) {
            QString p = url.toLocalFile().toLower();
            if (p.endsWith(".png") || p.endsWith(".jpg") || p.endsWith(".jpeg"))
                return true;
        }
        return false;
    }

    void onDropToNewNode(const QMimeData* mimeData, WarNode* node, void* modData) override {
        // node 已经创建完毕，primary_mod_type 也已经设置为本模组，
        // modData 已通过 onCreateNode 分配好。模组在这里填自己的数据。
        auto* d = static_cast<PrivateData*>(modData);
        if (mimeData->hasUrls() && !mimeData->urls().isEmpty()) {
            QString path = mimeData->urls().first().toLocalFile();
            d->somePath = path;
            d->cachedPixmap.load(path);
        }
    }

4.1 嵌入 Widget（WebMod 这种需要浏览器视图的场景）
----------------------------------------------------------------------

当节点内容需要真实的 Qt Widget（如 QWebEngineView 渲染网页、
原生 QMediaPlayer 控件等），请实现嵌入 Widget 接口：

    // 返回 true 表示"该模组需要嵌入 widget"
    bool hasEmbeddedWidget() const override { return true; }

    // 创建嵌入的 widget。parent 是 QGraphicsProxyWidget（由主程序创建）
    QWidget* createEmbeddedWidget(WarNode* /*node*/, void* modData,
        QWidget* parent) override
    {
        auto* d = static_cast<PrivateData*>(modData);
        auto* view = new QWebEngineView(parent);
        d->webView = view;  // 记录指针以便后续更新
        view->setUrl(QUrl("about:blank"));
        return view;
    }

    // 几何变化时通知模组（缩放/移动节点时）
    void updateEmbeddedWidgetGeometry(QWidget* widget,
        const QRectF& sceneRect, double zoomLevel) override
    {
        // sceneRect 是节点在 scene 中的矩形
        // zoomLevel 可用于调整细节显示
        widget->setGeometry(sceneRect.toRect());
    }

    // 销毁嵌入的 widget（模组自己负责清理子资源）
    void destroyEmbeddedWidget(QWidget* /*widget*/, void* modData) override {
        auto* d = static_cast<PrivateData*>(modData);
        d->webView = nullptr;
    }

    // 当前是否处于"嵌入 widget 显示模式"
    // 返回 true 时，主程序不会再调用 onPaint 绘制底层内容
    bool isEmbeddedWidgetActive(void* modData) const override {
        auto* d = static_cast<PrivateData*>(modData);
        return d && d->showEmbedded;
    }

4.2 存档资源打包（ImageMod / VideoMod 这种需要携带外部文件的主模组）
----------------------------------------------------------------------

主程序"文件夹存档"（saveToFolder）会把节点保存到 board.json，并
把所有外部文件拷贝到 <folder>/mod_data/<modId>/<nodeId>_<basename>，
实现方法：

    // 返回该节点上需要被打包的外部文件的"本地绝对路径"列表
    QStringList collectExternalFiles(const WarNode* /*node*/,
        void* modData) const override
    {
        auto* d = static_cast<PrivateData*>(modData);
        QStringList result;
        if (d && !d->somePath.isEmpty())
            result << d->somePath;
        return result;
    }

    // 加载文件夹存档时，主程序告知模组：
    //   archiveDir      = <folder> 存档根目录
    //   modDataSubdir   = <folder>/mod_data/<modId>/
    // 模组需要据此反序列化 d->somePath（可能从相对路径转换为绝对路径）
    void setArchiveBaseDir(const QString& archiveDir,
        const QString& modDataSubdir) override
    {
        // 把路径保存到模组级静态变量，后续 deserialize() 里再解析
        ImageMod::setCurrentDocumentDir(archiveDir);
        modDataSubdir(); // 也可缓存
    }

4.3 模组设置界面（全局设置，和节点无关）
----------------------------------------------------------------------

    // 返回 true 时，"模组设置"页面对该模组显示"设置"按钮
    bool hasSettings() const override { return true; }

    // 创建设置 widget（parent 由主程序管理生命周期）
    QWidget* createSettingsWidget(QWidget* parent) override {
        auto* w = new QWidget(parent);
        auto* layout = new QVBoxLayout(w);
        auto* check = new QCheckBox("默认显示原图", w);
        check->setChecked(ImageMod::defaultShowOriginal());
        check->setObjectName("showOriginalCheck");  // 用 objectName 存状态引用
        layout->addWidget(check);
        layout->addStretch();
        return w;
    }

    // 保存设置：从 widget 上读取值写回
    void saveSettings(QWidget* widget) override {
        auto* check = widget->findChild<QCheckBox*>("showOriginalCheck");
        if (check) ImageMod::setDefaultShowOriginal(check->isChecked());
    }

4.4 键位绑定（模组自己的快捷键，在全局"键位设置"页展示）

    // 返回模组拥有的键位绑定列表
    std::vector<KeyBinding> getKeyBindings() const override {
        return {
            { "builtin.image.reload", "重新加载图片", "图片模组", "F5" },
            { "builtin.image.toggle", "切换原图/缩略图", "图片模组", "Ctrl+M" },

    ModInteractionResult onKeyPress(QKeyEvent* event,

    {
        QKeySequence seq = KeyBindingRegistry::instance()
            .getQKeySequence("builtin.image.reload");
        if (!seq.isEmpty() && seq.matches(event->key() | event->modifiers())
                == QKeySequence::ExactMatch) {
            // 执行重载逻辑...
            return ModInteractionResult::Consumed;
        }
        return ModInteractionResult::Ignored;
    }

4.5 编辑器 Widget（节点专属编辑面板，替代/补充默认文本编辑）

    // 节点第一次进入编辑状态时调用
    QWidget* createEditorWidget(WarNode* node, void* modData,

    {
        auto* edit = new QTextEdit(parent);
        edit->setPlainText(QString::fromStdString(node->full_text));

    }

    // 节点数据变化时，让编辑器同步更新（罕见使用）

        void* modData) override {}

4.6 连线钩子（模组控制连接权限与响应连接事件）
----------------------------------------------------------------------

    // 是否允许从 from 连向 to（两个节点都可以用本模组的数据做业务判断）
    bool canConnectTo(const WarNode* from, const WarNode* to,
        void* /*modData*/) const override
    {
        // 例如：图片模组节点允许作为源节点连接给任何目标
        Q_UNUSED(from); Q_UNUSED(to);
        return true;
    }

    // 连线被创建/删除时，模组可以更新私有数据或节点状态
    void onConnectionCreated(const WarLink& /*link*/, void* modData) override {}
    void onConnectionRemoved(const WarLink& /*link*/, void* modData) override {}

4.7 辅助模组自动附加（shouldAutoAttach）
----------------------------------------------------------------------

辅助模组可以实现 shouldAutoAttach，在节点创建完成后由主程序调用
ModManager::autoAttachAuxiliaryMods() 自动扫描附加：

    bool shouldAutoAttach(const WarNode* node) const override {
        // 例如：所有图片节点自动附加标注模组
        return node->primary_mod_type == "builtin.image";
    }

================================================================================
五、关键概念详解
================================================================================

【私有数据（PrivateData）生命周期】
- 每个节点绑定模组后，会为该节点分配一个私有数据实例（void*）。
- 分配/释放由模组自己负责（onCreateNode / onDestroyNode）。
- WarNode 只存可序列化的 JSON（primary_mod_data / auxiliary_mod_data），
  不持有运行时指针，避免污染拷贝/移动语义。
- ModManager 内部维护： nodeId -> (modId -> void*) 的运行时映射表。

【序列化流程】
保存文件时（WarRoomMainWindow::onSaveAction）：
  1. 先调用 ModManager::saveNodeModData(node)
     - 对每个模组：onNodeSaved()  →  serialize() → 写回 WarNode::*_mod_data
  2. 然后 WarNode 序列化为 JSON（含 *_mod_data）
  3. 最后 JSON 写入 .warroom 文件或 board.json

加载文件时：
  1. WarNode 从 JSON 反序列化（*_mod_data 已填充）
  2. ModManager::initNodeModData(node, item)
     - onCreateNode() 创建私有数据
     - deserialize() 从 JSON 填值
     - onNodeLoaded() 结束钩子

文件夹存档时额外调用：
  - 保存：WarLink* 主模组的 collectExternalFiles() → 拷贝资源到 mod_data/
  - 加载：setArchiveBaseDir() → 模组拿到根目录以便解析相对路径

【渲染责任链】
NodeGraphicsItem::paint：
  1. 绘制选中状态时的外框（可选）
  2. 主模组的 onPaint()：
     - 返回 true  → 跳过默认文本/背景，直接进入辅助模组
     - 返回 false → 继续绘制默认标题、长文本等
  3. 按 ModPriority 高→低顺序，遍历辅助模组的 onPaint()
  4. 最后绘制边框、选中高亮、缩放手柄、锚点等 UI

【交互责任链】
事件分发顺序：
  1. NodeGraphicsItem 接收到事件
  2. 只读模式（isReadOnly）校验（只读可能阻止部分写操作）
  3. 先主模组 → 再按 ModPriority 遍历辅助模组
  4. 每个模组返回 Ignored 时继续向下；Handled/Consumed 停止
  5. 所有模组都 Ignored 时，执行 NodeGraphicsItem 的默认行为

【ModPriority 枚举】
    Lowest / Low / Normal / High / Highest
数值越大优先级越高：
  - onPaint  中：优先级高的 辅助模组 后绘制（盖在上面）
  - 事件分发中：优先级高的先收到事件

================================================================================
六、模组 ID & 命名规范
================================================================================

- 官方内置：builtin.*
    builtin.image      图片节点
    builtin.video      视频节点
    builtin.web        网页节点
    builtin.annotation 标注辅助模组

- 社区自定义：建议用 custom.* 或 作者/组织名.*
    custom.excel       自定义 Excel 模组
    org.example.ai     作者/组织名作为前缀

- 避免与内置模组 ID 冲突，否则后注册的会覆盖。

================================================================================
七、动态库模组（预留接口，当前未在主程序默认启用）
================================================================================

ModManager 已实现动态库加载能力（ModManager::loadModFromLibrary）：
  1. 把模组编译成 DLL
  2. 导出 extern "C" NodeMod* createMod() 函数
  3. 返回 new 出来的模组指针（由 ModManager 接管 std::unique_ptr）

manifest.json 格式（放置在 mods/<modName>/manifest.json）：
    { "id": "custom.xxx", "entry": "mod.dll" }

主程序通过 WarRoomMainWindow 调用
ModManager::instance().loadModsFromDirectory("<mods目录>") 即可。

> 当前版本主程序默认路径尚未自动扫描 mods/ 目录，如需要可在
> WarRoomMainWindow 构造函数中显式调用 loadModsFromDirectory 启用。

================================================================================
八、常见问题
================================================================================

Q1. 模组修改了 PrivateData 后节点显示没有刷新？
A.  右键菜单场景下使用 ctx.requestNodeRefresh(ctx.nodeId)。
    其他场景：通过持有 NodeGraphicsItem* 在 onCreateNode 里保存，
    然后调用 item->update()；或者调用 scene()->update()。

Q2. 为什么我在 onCreateNode 中读到 primary_mod_data 是空？
A.  调用顺序是：onCreateNode → deserialize → onNodeLoaded。
    想读取保存过的 JSON，在 deserialize 或 onNodeLoaded 中处理。

Q3. 辅助模组想叠加绘制，应该 onPaint 返回什么？
A.  返回 false，让渲染链继续。主模组才常常返回 true。

Q4. 拖放文件到空白处，ImageMod 会自动创建节点，这个能力如何复用？
A.  WarRoomMainWindow 的拖放逻辑会遍历所有主模组调用
    canCreateNodeFromDrop，返回 true 的第一个会被选中作为新节点的
    primary_mod_type，然后自动调用 onDropToNewNode。

Q5. 文件夹存档之后，我存的相对路径如何在加载时解析？
A.  使用 collectExternalFiles 把绝对路径返回，框架自动拷贝；
    加载时框架调用 setArchiveBaseDir 给你存档根目录与 mod_data 子目录，
    你在 deserialize 里判断 somePath 是相对路径就用 QDir(archiveDir).filePath(...)
    还原为绝对路径。ImageMod 中 currentDocumentDir() 静态变量可以参考。

Q6. 模组有哪些线程/可重入注意事项？
A.  - 所有 NodeMod 虚函数都在 Qt GUI 线程中调用（paintEvent、事件循环）。
    - ModManager 的取/存私有数据与注册都是加锁的，但虚函数调用本身
      不在锁内（避免重入死锁）。
    - 不要在 deserialize / onCreateNode 里直接依赖 ModManager 互查数据，
      此时节点可能尚未完成映射。

Q7. 如何支持 Undo/Redo？
A.  模组修改 WarNode 模型数据时，建议使用 core/command 下的命令对象
    （例如已实现的 SetNodeColorCommand / EditNodeCommand）。
    模组自定义数据在 PrivateData 里（不在 WarNode）无法被默认命令处理，
    若想支持模组私有数据 undo/redo，建议新写一条 command 并在 command
    里通过 ModManager::getNodePrivate 取私有数据做备份/还原。
